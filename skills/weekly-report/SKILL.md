# 周报流程

1. **收集事实**：`git.log`（最近 7 天，或用户指定区间；多个仓库就各拉一次）。没有 git 就问用户要素材，别编。
2. **归类**：按"模块/项目"分组，每组 2–5 条；每条写"做了什么 + 结果/状态"，动词开头，不写过程流水账。
3. **三段结构**：本周完成 / 进行中与风险 / 下周计划。风险要具体（缺什么、卡在谁、需要谁拍板），别写"持续推进"。
4. **数字要真**：提交数、修复的 issue 数、上线次数只写你从 git.log 数出来的；数不出来就不写数字。
5. **成文**：先给用户看 Markdown 草稿；用户点头后再 `doc.write.docx`（文件名 `周报-YYYY-MM-DD.docx`，overwrite 默认 false）。
6. **口吻**：给上级看的正式文体，不用"哥哥姐姐/亲"之类自来熟；不写与汇报无关的内部缺口清单。

## 别做
- 别把 diff 内容贴进周报；别猜没在 git 里的工作；别在没确认前直接生成 docx。
